# Azure Infrastructure Definition

> **MILESTONE 1 COMPLETE AND VALIDATED — DEVELOPMENT PROVISIONED; PRODUCTION DEFINITION-ONLY**

Unit 2 originally established the approved Milestone 1 infrastructure definitions. Later governed
units used the development-specific definitions and overlays to provision and validate the supported
development foundation recorded in the Milestone 1 evidence. The production parameterization remains
definition-only, and no production deployment is claimed.

## Structure and responsibilities

- `bicep/main.bicep` is the subscription-scoped composition. It declares one environment-specific
  resource group and composes all bounded modules.
- `bicep/environments/dev.bicepparam` and `prod.bicepparam` define the foundation environments.
  Unit-specific development overlays contain only their bounded non-secret parameters.
- `storage.bicep` defines secure ADLS Gen2 storage and raw, processed, curated, and quarantine
  containers. Raw data is cooled but never lifecycle-deleted; derived data retention is configurable.
- `data-factory.bicep` defines ADF with a system-assigned identity, but no pipelines or activities.
- `container-registry.bicep` defines a cost-conscious, admin-disabled image registry.
- `monitoring.bicep` defines the Log Analytics dependency required by Container Apps.
- `container-apps-environment.bicep` defines the managed execution environment.
- `container-apps-job.bicep` defines a manual, identity-ready future transformation job interface.
  Its root deployment is gated by `deployTransformationJob`, which is `false` in both current
  environment parameter files.
- `key-vault.bicep` defines an RBAC-ready, purge-protected vault containing no secrets.
- `postgresql.bicep` defines an Entra-only, bounded PostgreSQL Flexible Server with no schemas or data.
- `unit9-private-network.bicep` composes the development-only private network, PostgreSQL Private
  Endpoint/DNS, and future replacement network-capable Container Apps Environment. It references
  the existing PostgreSQL server and Log Analytics workspace and performs no Job cutover.

## Prerequisites and local validation

Azure CLI with Bicep CLI is required. Login is not required for local compilation.

```powershell
az version
az bicep version
az bicep build --file infrastructure/bicep/main.bicep
az bicep build-params --file infrastructure/bicep/environments/dev.bicepparam
az bicep build-params --file infrastructure/bicep/environments/prod.bicepparam
az bicep lint --file infrastructure/bicep/main.bicep
Get-ChildItem infrastructure/bicep -Recurse -Include *.bicep,*.bicepparam |
  ForEach-Object { az bicep format --file $_.FullName }
```

These commands compile, lint, or format locally. Do not run `az deployment` without separate
governance authorization.

## Environments, naming, and tags

`development` maps to the `dev` name segment and `production` maps to `prod`. Every global name
also includes a deterministic `uniqueString` suffix derived from subscription, environment, and
region. The parameter files intentionally select distinct capacity and recovery settings.

All supported resources receive `repository`, `workload`, `environment`, and `managedBy` tags plus
the governed `project`, `portfolio`, and `costOwner` values supplied by the parameter files.

## Outputs and later-unit interfaces

The root exposes resource IDs, data container names, ADF and job principal IDs, registry login
server, PostgreSQL FQDN, and other identifiers required by later units. It does not create role
assignments. The Container Apps Job image value is an explicit Unit 3 interface marker—not a built
or runnable image. Actual Job deployment remains deferred until later governed work supplies the
real image and required registry-pull authorization. The monitoring shared key is generated by
Azure at deployment time, passed only through secure module values, and never emitted from the root.

No password, token, access key, private key, connection string, or secret value belongs in a
`.bicepparam` file. Workload authorization and the complete RBAC graph remain Unit 5 responsibilities.
